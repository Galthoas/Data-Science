# Phase 7 — Portfolio Capstone Projects (6–8 weeks, ~90 hrs)

By now you've produced several project drafts along the way (Phase 3's EDA project, Phase 4's HarvardX capstones, Phase 5's ML project, Phase 6's deep learning project). This phase is dedicated time to **polish the best of them into a genuinely hireable portfolio** — plus fill any gap in the four project types below that you don't already have covered.

See [`projects/README.md`](../../projects/README.md) in the repo root for the detailed requirements each project needs to meet (clear README, clean code, honest write-up of results and limitations, etc.) — this phase is about *executing* against those requirements, not re-explaining them.

## The four project types you want represented

1. **End-to-end EDA + storytelling project** — likely already drafted in Phase 3. Polish it: tighter narrative, better visualizations, a clear "so what."
2. **Supervised ML prediction project** — from Phase 5, or the Google Advanced Data Analytics capstone. Make sure model evaluation is rigorous and honestly reported, including where the model *fails*.
3. **SQL / data pipeline or dashboard project** — this is likely your one gap. Pick a dataset, design a small relational schema, load it into SQLite or PostgreSQL, write meaningful queries, and optionally connect it to a free dashboard tool (Tableau Public, Google Data Studio/Looker Studio, or even a matplotlib/Streamlit dashboard) to visualize the output. This project specifically demonstrates the "can work with data as it actually lives inside a company" skill that a pure-notebook portfolio misses.
4. **Deep learning or NLP project** — from Phase 6.

## Polish checklist for every project

- README that opens with a 2–3 sentence summary a non-technical hiring manager could understand, before any code.
- Clear statement of the question you were answering and why it matters.
- Clean, commented code — no dead cells, no "just testing this" leftovers.
- Honest results section, including limitations (a data scientist who reports only successes reads as inexperienced, not impressive).
- Where possible, one clear visualization that would work as a standalone image in a presentation.

## You're done when

- Four projects, of the four types above, are each in their own subfolder under `projects/`, each with a polished README.
- Your GitHub profile README (see `resources/free-course-catalog.md` for a guide, or just ask for help writing one) links to all four.
- You could talk through any one of these four projects, unscripted, for five minutes in an interview.
