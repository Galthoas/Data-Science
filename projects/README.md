# Portfolio Projects

This folder is where your actual portfolio lives — the thing hiring managers will look at more closely than any certificate. As you complete each phase, add a project here in its own subfolder.

## Suggested structure

```
projects/
  01-eda-storytelling/
    README.md
    notebook.ipynb
    data/ (or a note on where to download it, if too large to commit)
  02-ml-prediction/
    README.md
    notebook.ipynb
  03-sql-pipeline-dashboard/
    README.md
    schema.sql
    queries.sql
  04-deep-learning-nlp/
    README.md
    notebook.ipynb
```

## What every project README needs

1. **A 2–3 sentence summary** a non-technical person could understand, at the top, before any code or jargon.
2. **The question you set out to answer**, and why it matters.
3. **Data source** — where it came from, and a link if it's public.
4. **Approach** — what you did, briefly, in plain language (save the code detail for the notebook itself).
5. **Results** — the actual findings or model performance, stated honestly, including limitations. A project that says "this model gets 99% accuracy" with no caveats reads as inexperienced; one that says "72% accuracy, and here's the specific type of case it struggles with and why" reads as someone who understands their own work.
6. **What you'd do with more time/data** — shows growth mindset and awareness of the project's boundaries.

## Project ideas by type

**EDA / storytelling:** public health data, sports statistics, local economic data (MTSU's home state of Tennessee has good open state-level datasets), music/streaming data, climate data.

**ML prediction:** housing price prediction, customer churn prediction, credit risk, loan default, disease diagnosis prediction (using public, de-identified datasets only) — classic, well-understood problems are fine for a portfolio; the point is demonstrating rigor, not novelty.

**SQL / pipeline / dashboard:** design a small schema for a business domain you understand (your business support background is a real asset here — model something like a support ticket system, an inventory system, or a customer database), populate it with realistic sample or public data, and build a small dashboard on top.

**Deep learning / NLP:** image classification on a dataset you choose (not just MNIST — pick something with a real-world angle), or a text classification/sentiment project using public review or social data.

## Tying it together on GitHub

Once you have all four, add a short **profile README** on your GitHub account (a special repo named exactly your username creates this) that briefly introduces you and links to each project with a one-line description. This is often the very first thing a recruiter or hiring manager sees when they click through from your resume.
